How it works

Two agents get the same goal and the same model. One sees screenshots. The other gets only what a screen reader gets.

  1. Run both

    Each agent shops in its own sandbox with a real browser.

  2. Find the blocker

    Where the blind agent stalls, Earshot names the element and the WCAG rule.

  3. Patch it

    A small attribute fix, like role="radio". No generated code runs.

  4. Prove it

    A fresh blind agent reruns the journey. The fix counts only if it gets through.

A page can pass every check and still lose the sale

Checkers list rule violations. They can’t tell you which one stops a screen-reader user from paying. Earshot can, and since June 2025 the European Accessibility Act makes that a legal issue for shops in the EU.

  • Finds what blocks a purchase

    Not a list of rules. The one step a customer can’t get past.

  • Gives a fix you can ship

    Roles, ARIA and tabindex. Readable in seconds.

  • Proves the fix works

    Checked by a new agent in a new sandbox, in about 97 seconds.

Architecture

The control plane plans each step and holds every key. Sandboxes only act. It all runs on one Vultr VM, with the model on Vultr Serverless Inference.

Vultr Cloud Compute one VM in Frankfurt

Vultr Cloud Compute
Hosts everything. Each agent gets a gVisor container that starts in about a second and is deleted after one job.
Vultr Serverless Inference
Runs both agents, the screen check, the patches and the voice. The key never leaves the control plane, and no GPU is needed.
Vultr API and firewall
One script provisions the VM. Only ports 80 and 443 are public.

Contained by design

The demo checkout hides a prompt injection only the blind agent can hear. It was obeyed 0 times in 12 runs. If it ever is, the proxy blocks it.
