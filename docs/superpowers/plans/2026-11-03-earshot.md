# Earshot Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship Earshot, a public web app on a Vultr VM where a sighted (vision) agent and a blind (accessibility-tree-only) agent attempt the same shopping journey in disposable gVisor sandboxes. Every divergence is attributed to an element, a failure category and a WCAG rule, and fixes are generated and verified by stacked blind reruns. A prompt injection is caught by the real egress proxy.

**Architecture:**
- A trusted **control** server (Fastify) owns all secrets and LLM calls. It spawns one Docker container per agent run.
- Each container is a **keyless browser runner** (Playwright + Chromium) driven over **stdin/stdout JSON-lines RPC**, so sandboxes need no network path to control at all.
- Sandboxes sit on an `internal` Docker network whose only other member is the **egress proxy**, which enforces a per-sandbox allowlist and reports blocks to control.
- A React UI streams run events over SSE.

**Tech Stack:**
- Node 24, TypeScript 5, pnpm 10 workspaces.
- Fastify 5, dockerode 5, Playwright 1.64.1, axe-core 4.14, openai SDK 5 (pointed at Vultr Serverless Inference).
- React 19 + Vite 7, Vitest 4.
- Docker + gVisor `runsc`, Caddy 2, Ubuntu 24.04 on Vultr `vc2-2c-4gb` in `fra`.

**Spec:** [docs/superpowers/specs/2026-11-03-earshot-design.md](../specs/2026-11-03-earshot-design.md). Read it before starting any task. Section references like §5.3 point into it.

## Global Constraints

- Vultr Serverless Inference (`https://api.vultrinference.com/v1`) is the **only** model provider: agents, fixes, TTS and the optional injection flag.
- **No secret ever enters a sandbox container.** Sandbox env contains only `EARSHOT_PROXY` and `EARSHOT_MODE`. Assert it in tests.
- Sandbox limits: `Memory 1 GiB`, `NanoCpus 0.75e9`, `PidsLimit 256`, `ReadonlyRootfs true` + tmpfs `/tmp` and `/home/pwuser`, `User pwuser`, `CapDrop ALL`, `SecurityOpt no-new-privileges`, runtime from `SANDBOX_RUNTIME` (`runsc` on the VM, `runc` locally), `AutoRemove false` (control removes explicitly), label `earshot.sandbox=1` + `earshot.run=<runId>`.
- Agent budget: **15 steps**, **120 s** wall-clock per agent, stop after **3 consecutive no-progress steps**.
- Fix loop: **max 4 iterations**, **2 patch attempts per finding**. Approval timeout **60 s** = denied. Reaching the gate = journey complete.
- One run executes at a time; queue max 5. Demo-store runs are open (rate limit **3 runs / hour / IP**); any-URL runs require `ACCESS_CODE`.
- Both agents use the **same model** (`AGENT_MODEL`); only the observation channel differs.
- Every Vultr resource gets tag/label `agent-rush`. **Creating billable resources (inference subscription, VM) or pushing to GitHub requires explicit owner confirmation at that step.**
- Copy fixed by spec: hero line "Rules don't fail customers. Journeys do."; store brand "Kaffeebohne Roasters"; test card `4242 4242 4242 4242`; injection host `cardcheck.attacker.invalid`.
- Never fake containment: every BLOCKED event in the UI originates from the proxy.
- Licence MIT. Repo name `Earshot`.
- **Implementation call:** attribution uses a fresh **inspector sandbox** that replays the sighted agent's recorded actions up to the target step (§5.4 lists replay as the fallback; using it always is simpler and deterministic). The sighted sandbox is destroyed as soon as the sighted agent finishes.

## Review Focus

1. **Blind agent tries to act on non-interactive AX nodes** (generic/StaticText). Expected: the runner rejects the action with `not-actionable`, as a screen-reader user couldn't activate it. Otherwise the planted div bugs never block. Test in Task 4.
2. **Model returns no tool call, malformed JSON args or an unknown ref.** Expected: one corrective retry, then the step is recorded as `error` and counts as no-progress. Never a crash or a hung run. Test in Task 9.
3. **A run throws midway (model 5xx, container OOM, runner crash).** Expected: every container for that run is removed, `sandbox.destroyed` is emitted with reason `error`, and the queue moves on. A boot-time reaper removes leftover `earshot.sandbox=1` containers. Test in Task 7 and Task 14.
4. **Any-URL target or redirect resolving to private, loopback, link-local or metadata IPs** (including DNS names that resolve there). Expected: the proxy denies after resolving DNS and emits BLOCKED. Test in Task 3.
5. **Approve/deny called with a missing or wrong token, twice, or after the 60 s timeout.** Expected: 403 for a bad token, 409 when already resolved, and the agent's outcome unchanged. Test in Task 14.

### Task 3: Egress proxy with per-sandbox policy

**Files:**
- Create: `proxy/{package.json,tsconfig.json,Dockerfile}`, `proxy/src/{policy.ts,server.ts,ip.ts}`
- Test: `proxy/test/policy.test.ts`, `proxy/test/server.test.ts`

**Interfaces:**
- Produces:
  - `type SandboxPolicy = { runId: string; agent: AgentId; mode: RunMode; allowHosts: string[] }`.
  - `decide(target: { host: string; port: number; resolvedIps: string[] }, policy: SandboxPolicy | undefined): { allow: true } | { allow: false; reason: 'no-policy' | 'not-allowlisted' | 'private-address' }`.
- Admin API on `:3129`, header `x-admin-token: $PROXY_ADMIN_TOKEN`:
  - `PUT /policy/:ip` with body `SandboxPolicy`;
  - `DELETE /policy/:ip`.
- Proxy on `:3128` (HTTP absolute-URI + CONNECT). It POSTs denials to `$CONTROL_EVENTS_URL` (`http://control:3000/internal/proxy-events`), header `x-events-token`, body `{ ip, method, host, path, reason }`. For CONNECT, `path` is `''`.
- Control maps the source IP back to the run.

### Task 12: Fix generation + stacking verify loop

**Files:**
- Create: `apps/control/src/fix/{patch-schema.ts,generate.ts,loop.ts,diff.ts}`
- Test: `apps/control/test/patch-schema.test.ts`, `apps/control/test/fix-loop.test.ts`

**Interfaces:**
- `patch-schema.ts`: `PATCH_JSON_SCHEMA` (the JSON Schema for `Patch` minus `findingId`; attribute keys limited to the `Patch` union; no other properties) and `validatePatch(x: unknown, finding: Finding): Patch | { error: string }`.
  - Reject selectors containing `script`, `<`, `{`, or longer than 200 chars.
  - Reject any attribute value longer than 200 chars, or containing `<`.
  - The selector must match the finding's element. This is checked later via `patchStatus` > 0.
- `generate.ts`: `generatePatch(inference, finding, previousAttempt?: { patch: Patch; failure: string }): Promise<Patch | { error }>`. Prompt with the finding (snippet, categories, axe rules, blind excerpt) and use `inference.json` with the schema.
- `diff.ts`: `renderDiff(beforeSnippet: string, afterSnippet: string): string` (unified diff via the `diff` package).
- `loop.ts`:
  ```ts
  runFixLoop(ctx: { runId; goal; startUrl; sighted: AgentResult; firstFinding: Finding; inference; createSandbox; runAgentFn: typeof runAgent; attributeFn: typeof attribute; emit; gate }): Promise<{ verified: boolean; patches: Patch[]; findings: Finding[] }>
  ```
  This is the algorithm in spec §5.4. Iterations ≤ 4, attempts per finding ≤ 2. Each rerun is agent `rerun-<n>` in a fresh sandbox with all accepted patches.
  - A patch is **accepted** when the rerun's milestones include the finding's milestone **and** `patchStatus[findingId] > 0`.
  - Then mark the finding `verified` and emit `fix.result{verified:true}`. The diff comes from the rerun's `inspect` snippet versus the finding snippet: call `inspect` on the rerun sandbox **before** destroying it.
  - If the rerun reaches the gate → `verified: true`, stop.
  - If it stalls at a later milestone → `attributeFn` against the sighted result, using the stacked patches → the new finding → continue.
  - Unconfirmed new divergence → stop with `verified:false`.

  - `patch with 0 matches is retried once then finding unverified and loop stops`;
  - `validatePatch rejects script selectors and unknown attributes`;
  - `max 4 iterations`.
